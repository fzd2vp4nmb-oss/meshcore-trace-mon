Period:
















    Compares the path taken by adverts (repeater flood, all nodes)
    with the path taken by Sonar messages (a message sent on purpose
    from a known node, so its source and send time are known). Both are read
    from the paths recorded by the tracers. Source and tracer are two
    roles, not two kinds of node: the source is the node that transmits a
    packet, the tracer is another trace-mon node that receives it and
    records its path. The same trace-mon node is the source of the packets
    it transmits and the tracer of those it receives. The aim is to see how far
    each kind of packet really travels, and which repeaters are seen
    forwarding at depth. It is an inference from recorded paths, not a
    measurement of any repeater's settings. The only settings known are the
    flood limits of the repeaters managed by trace-mon (panel 6).

5. Repeaters seen at depth



    Repeaters seen forwarding at position 9 or beyond in the recorded paths.

    columns add what is known about the advert limit (panel 6).




    
    






    





6. Operating limits



    A repeater forwards a flooded packet only up to a number of hops, set by
    three settings: Flood Max Hops (Unscoped),
    Flood Max Hops (Advert) and Flood Max Hops. trace-mon reads
    them only from the repeaters it manages; for every other repeater on a
    path they are not known, and only the highest position at which it was
    seen forwarding is. The effective cap used here is a working hypothesis:
    advert without region = min(Unscoped, Advert), advert with region =
    Advert, message without region = min(Unscoped, Flood Max Hops), message
    with region = Flood Max Hops. A repeater at position k of a path
    can appear only if k is within its cap. In panels 3, 4 and 5,
    “would stop” and “not stopped” say whether the
    other kind of packet, with the same scope, could have followed the same
    path, judged only on the settings known: it describes a path, it does not
    classify a repeater.







    
Settings of the repeaters managed by trace-mon

    

        The list of repeaters is not fixed: each manager of trace-mon can add
        or remove repeaters, and a node may start without any and get one
        later. The table follows the period selected above: it shows the
        settings in force at the end of the period, only for the
        repeaters whose settings are known in it. A repeater added during the
        period is marked added in this period; one that stopped being
        read, no longer read. The readings are kept even after a
        repeater is removed from the configuration, so it still counts for
        the periods in which it was read.
    

    

        

    

    


    
Where the settings come from

    

        Each node reads the settings of its own repeaters, but a repeater of
        one node also affects the packets seen at every other node, so the
        readings of all nodes are combined. A node with no managed repeater
        adds nothing: it is normal until one is added.
    

    

        

    


    
Gateway ceiling at each tracer

    

        The gateway is the last repeater before the tracer. A copy cannot
        have more hops than its gateway's cap, so where the gateways are
        capped low the tracer cannot see deep paths of that kind, whatever
        the repeaters in the middle do. Counted over all copies of the
        period, from any source.
